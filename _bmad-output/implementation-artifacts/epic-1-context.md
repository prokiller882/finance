# Epic 1 Context: Обновление без потери данных

<!-- Compiled from planning artifacts. Edit freely. Regenerate with compile-epic-context if planning docs change. -->

## Goal

Обновление на телефоне не должно стоить пользователю данных: операции, счета и настройки сохраняются, а несовместимая или повреждённая копия открывает безопасный экран с экспортом, импортом, восстановлением pre-v4 и сбросом вместо пустого приложения. Эпик не добавляет пользовательских функций, но снимает риск «обновился и потерял год операций» и открывает дорогу эпикам 2–5. Два релиза: A — forward-safe чтение и safe mode на текущей схеме с проверкой установки на телефоне; B — схема v4 с полями-умолчаниями, чтобы следующие эпики не мигрировали повторно.

## Stories

- Story 1.1: Сохранение честно сообщает результат
- Story 1.2: Безопасный режим вместо пустого приложения
- Story 1.3: Схема v4 без потери полей
- Story 1.4: Системные категории не выбираются вручную

## Requirements & Constraints

- Копии v1–v3 мигрируют в v4 без потери операций, счетов, категорий, планов и настроек; v3 → v4 проставляет пустые списки и нулевые нормы, не создаёт переводов задним числом, не переписывает операции и планы.
- Копия с версией выше текущей отклоняется с понятной ошибкой, состояние не меняется. Неизвестные поля и ключи сохраняются; если ключ сохранить нельзя — список предупреждений, видимый пользователю.
- Импорт подтверждается, полностью валидируется до применения и заменяет состояние целиком; отмена диалога не даёт тоста и не меняет дату копии. Видны дата последней копии и предупреждение старше 30 дней; выгрузка — через «Поделиться».
- Импорт с ошибкой не перезаписывает данные; повреждённое хранилище даёт ошибку и копию повреждённых данных, без молчаливой потери. Живой конверт ≤ 4,5 MiB; квота видима, без тихой обрезки.
- Сброс требует подтверждения; изменение в другой вкладке отражается через событие хранилища, а в safe mode показывает баннер, не подменяя состояние.
- После первого открытия всё работает офлайн. Каждый новый файл оболочки попадает в `PRECACHE`, `CACHE` поднимается, проверка precache проходит. Данные не покидают браузер, новых сетевых вызовов нет.
- Системная категория скрыта из общего выбора и не удаляется; удаление обычной категории по-прежнему обнуляет `categoryId`, не меняя тип операций.

## Technical Decisions

- Состояние меняется только через `store.commit(mutator)`, одно действие — одна атомарная мутация. Результат строго `{ ok: true }` или `{ ok: false, reason: 'invalid' | 'stale' | 'quota' | 'forward' }`; все проверки переводятся на `result.ok`, truthiness-проверок объекта нет. `stale` — устаревший базовый `rev`: запись не выполняется, чужая вкладка не перезаписывается; `quota` — видимый тост.
- `replace(next, { persist })` сохраняет первым и публикует только при успехе; при ошибке старое состояние остаётся в памяти и хранилище. Разрешён для импорта, сброса, восстановления pre-v4 и storage-события; в safe mode — только для подтверждённого восстановления.
- Производные величины считаются на чтении, в `state` не хранятся; только plain-объекты. Конверт: `schemaVersion, rev, updatedAt, settings, accounts, categories, transactions, budgets, plannedPayments, paymentOccurrences, obligations, obligationAdjustments`.
- `SCHEMA_VERSION = 4`; умолчания: `rev: 0`, `obligations: []`, `obligationAdjustments: []`, `savingsRateBp: 0`, `obligationId/principal/interest/sourceTransactionId/skipSavings: null`, `category.system: false`, `category.mark: null`, `plannedPayment.obligationId: null`, `plannedPayment.archived: false`, `anchorDay` из `startDate`, `obligation.archived: false`.
- `readState()`: разбор → версия → миграция → валидация; статусы `empty | ok | forward | corrupt`, `forward` — до миграции. `loadState()` сеет seed только на `empty`, не на `corrupt`.
- Перед первой записью v4 сырой v3 копируется в `finance-tracker:pre-v4`, только если помещается; иначе миграция прерывается, v3 не тронут. Копия удаляется лишь после подтверждения в настройках; `:corrupt` хранит первую копию и не перезаписывается.
- На `forward`/`corrupt` store и роутер не создаются, рендерится `screens/safeMode.js`, тема системная. Действия: экспорт сырых данных, импорт проверенной копии, восстановление pre-v4, сброс с подтверждением. После успешного `replace` `rev` берётся из нового состояния, экран перерисовывается без перезагрузки.
- `validateState` собирает все ошибки и возвращает `INVALID_STATE` со списком; `rev` — целое ≥ 0. Поле проходит шесть точек: `create` → `validate` → `toJSON` → `migrate` → `validateState` → `seed`.
- `sys-interest` создаётся через `Category.create` в seed и миграции: стабильный id, `system: true`, `kind: 'expense'`, валидные `color`/`icon`; исключена из проверки уникальности `(kind, name)`, скрыта из выбора, `deleteCategory` отказывает. `validateState` разрешает её только у операции с `obligationId`; ссылки — по id.
- Ошибки: `ValidationError(entity, field, message)`, `StorageError(code)` (`INVALID_STATE`, `UNSUPPORTED_VERSION`, `IMPORT_TOO_LARGE`, `PARSE_ERROR`); экран ловит и показывает тост. Слои только вниз: `screens/components → app.actions → domain/reports → models → format/util`; `app.js` — composition root; без сборки и зависимостей; ключ `finance-tracker:v1` не меняется; выкладка только в `/finance/`, `.nojekyll` обязателен.

## UX & Interaction Patterns

- Safe mode — экран в той же визуальной системе: токены `DESIGN.md`, слои `bg → surface → surface-muted` с границей 1 px, без теней и градиентов, один акцент.
- Ошибки, предупреждения миграции и квота видны текстом; пустые состояния не показывают выдуманных чисел; сброс и восстановление — после подтверждения. Поля 16 px, тач-цели ≥ 44 px, фокус 2 px, подписи sentence case без эмодзи.

## Cross-Story Dependencies

- Релиз A (1.1–1.2) выходит на текущей схеме; релиз B (1.3–1.4) — после проверки A на телефоне: установка, чтение v3, safe mode.
- 1.2 опирается на контракт результата и save-before-publish из 1.1; импорт в safe mode использует общую валидацию. 1.4 зависит от миграции и seed из 1.3.
- Эпик 1 — предпосылка эпиков 2–5: поля v4 уже есть. После него приложение работает как раньше плюс safe mode.
