## Intent

**Problem:** `store.commit()` возвращает boolean и глотает причину сбоя: переполненный `localStorage` выглядит как «сохранено», а вкладка с устаревшими данными молча перезаписывает чужую запись. Пользователь теряет операцию, не узнав об этом.

**Approach:** Ввести `rev` в конверт и единый результат `{ ok: true }` либо `{ ok: false, reason: 'invalid' | 'stale' | 'quota' }`: `commit` сверяет базовый `rev` до записи, `replace(…, { persist: true })` сохраняет до публикации, а экраны показывают тост по причине вместо truthiness-проверки объекта.

## Boundaries & Constraints

**Always:** `state` меняется только через `commit`/`replace`; `rev` — целое ≥ 0; при чтении сохранённого `rev` нечитаемые или нецелые данные считаются отсутствием записи (`null`) и запись не блокируют; производные величины считаются на чтении; ключ `finance-tracker:v1` и схема `v3` не меняются (релиз A); тексты русские, вывод — `toast`/`textContent`. При `stale` форма остаётся открытой с введёнными данными, показывается тост «Данные изменились в другой вкладке — повторите действие», состояние обновляет storage-событие; автоматического повтора мутации нет.

**Never:** поля и миграция v4, safe mode, `forward` (сторис 1.2–1.3); правки формул отчётов и оплаты; зависимости, сеть, `package.json`; тихая обрезка или сокрытие сбоя.

## I/O & Edge-Case Matrix

| Scenario | Input / State | Expected Output / Behavior | Error Handling |
|----------|--------------|---------------------------|----------------|
| `COMMIT_OK` | валидная мутация, `rev: 7` | `{ ok: true }`, сохранён `rev: 8`, подписчики уведомлены | — |
| `COMMIT_INVALID` | мутатор бросает `ValidationError` | `{ ok: false, reason: 'invalid' }`, данные не изменились | тост на экране |
| `COMMIT_STALE` | сохранён `rev: 9`, базовый `rev: 8` | `{ ok: false, reason: 'stale' }`, записи нет | тост, форма открыта, без автоповтора |
| `COMMIT_QUOTA` | `setItem` бросает `QuotaExceededError` | `{ ok: false, reason: 'quota' }`, память и хранилище целы | видимый тост |
| `REPLACE_OK` | `replace(next, { persist: true })` | сохранение, затем публикация; `rev` не меньше прежнего | — |
| `REPLACE_FAIL` | сохранение падает | публикации нет, старое состояние в памяти и хранилище | тот же `{ ok, reason }` |
| `STORAGE_EVENT` | `replace(next)` без `persist` | принимает `rev` другой вкладки без инкремента | — |
| `REV_INVALID` | `rev: -1` или `1.5` в `validateState` | `INVALID_STATE`, нарушение `rev` в общем `details` | — |

**Acceptance Criteria:**
- Given `commit` с валидной мутацией, when действие завершено, then `{ ok: true }`, `rev` +1, подписчики уведомлены, производных полей в `state` нет.
- Given `validateState` с нецелым или отрицательным `rev`, when проверка идёт, then `INVALID_STATE` содержит нарушение `rev` среди прочих, а не только первую ошибку.
- Given сохранённый `rev` больше базового, when вызывается `commit`, then запись не происходит, чужая вкладка не перезаписывается.
- Given `QuotaExceededError`, when `commit` или `replace(…, { persist: true })` сохраняет, then `quota`, данные целы, виден тост.
- Given `replace(next, { persist: true })` и сбой сохранения, when он происходит, then публикации нет, память и хранилище прежние.
- Given все вызовы в `app.js`, `screens/*`, `components/*`, when правка завершена, then нет `if (!saved)` и truthiness-проверок — только `result.ok`.
