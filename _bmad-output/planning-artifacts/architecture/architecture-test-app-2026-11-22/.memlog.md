- (decision) AD-3 money = safe integer minor units, rates = integer basis points (100% = 10000); parseAmount for money, parseRateBp for rates; floor division for interest/savings. Prevents floats and parseAmount misuse.

- (decision) AD-6 one balance primitive accountBalance/totalBalance; cash-flow closing = balance assets on the same date; liabilities are separate and never enter totalBalance. Prevents two balance definitions and a nonzero discrepancy.
- (decision) AD-7 obligation payment = one expense transaction with obligationId, signed principal and interest, amount = principal + interest; P&L uses interest, cash flow uses amount, journal shows amount with an interest note. Prevents the P&L/cash-flow split from being re-invented per report.
- (decision) AD-8 obligation debt is derived: remaining = initialPrincipal - sum(principal snapshots) + sum(adjustment deltas); no stored mutable remaining; corrections are separate adjustment records posted to P&L only. Prevents debt drift and corrections bypassing P&L.
- (decision) AD-9 each obligation owns exactly one linked PlannedPayment (obligationId, archived); recurrence.js remains the only date engine; general plan edits/deletes refuse linked plans. Prevents a second date engine and schedule/obligation desync.
- (decision) AD-10 obligation payment lifecycle is atomic and only via obligation actions: pay/edit/delete/archive; edit reverts and recomputes the split, keeps the occurrence paid; delete restores principal and pending; generic transaction mutations reject obligationId. Prevents double-counted debt and occurrence drift.
- (decision) AD-11 savings norm per savings account in basis points, sum over active savings <= 10000; generated transfers carry sourceTransactionId and a rate snapshot, are system-owned, and are recreated from snapshots on income edit. Prevents retroactive rate changes and duplicate/lost transfers.
- (decision) AD-12 DOM-free buildDailyLimit(state,{today}): base = cash/card/bank balances incl. archived, reserve from earliest overdue through next income, deficit window (nextIncome, today+1 month], days = date diff, skipped excluded. Prevents divergent limit math and skipping reserved payments.
