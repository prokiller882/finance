## Финансы — ванильный SPA

Личные финансы: счета, операции, отчёты, платёжный календарь. Чистый HTML/CSS/JS
на ES-модулях, без сборки и фреймворков; состояние — в `localStorage`.
Планы — `ROADMAP.md`, визуал и токены — `DESIGN.md`.

## Правила

- Коммитить в `main` разрешено; отдельная ветка — по желанию.
- Не выкладывать приложение в корень `prokiller882.github.io`: service worker
  со scope `/` перехватит соседние проекты. Только подпапка `/finance/`.
- Секретов в репозитории нет и быть не должно: данные живут в браузере.

## Где что лежит

- Вход: `index.html` (разметка экранов), `js/app.js` (bootstrap, `actions`, тема),
  `js/router.js` (hash-маршруты и overlays).
- Состояние: `js/store.js` (`commit()`), `js/storage.js` (ключи, миграции,
  импорт/экспорт, статусы старта), `js/schema.js` (`SCHEMA_VERSION = 4`).
- Чистые выборки без DOM: `js/journal.js`, `js/payments.js`, `js/recurrence.js`,
  `js/accounts.js`, `js/reports/*`.
- Экран — `section` в `index.html` + фабрика в `js/screens/`; overlay — компонент
  в `js/components/`. Безопасный экран — `main#safe-mode` вне шелла и
  `js/screens/safeMode.js`. Пошагово — `docs/extending.md`.
- Чек-лист перед сдачей правки — `docs/qa-checklist.md`.

## Запуск и проверка

- Только локальный сервер: `python3 -m http.server 8080` → http://localhost:8080.
  По `file://` ES-модули не работают.
- В репозитории нет `package.json`: `npm test` не запускается, автотестов в
  репозитории нет.
- Автотесты на машине разработчика лежат вне репозитория: `cd ~/finance-tests &&
  ./node-v22.11.0-linux-x64/bin/node <nav|direct|dom|logic|storage|imports|safe-mode>.mjs`.
  Без этого каталога проверка ручная.
- Продакшен — GitHub Pages: https://prokiller882.github.io/finance/. После push в
  `main` Pages пересобирает сайт; `.nojekyll` отключает Jekyll.
- Оболочка: `node scripts/check-precache.mjs` сверяет `PRECACHE` с файлами и требует
  новый `CACHE` при их правке. Pre-commit хук включается один раз на клон:
  `git config core.hooksPath .githooks`.

## Соглашения, отличные от стандартных

- Деньги — целые копейки (`125050` = 1250,50 ₽), никаких float; разбор — только
  `parseAmount()`. Делить на 100 можно лишь для отображения.
- Даты — строки `YYYY-MM-DD`, сравнение строками; арифметика — через `parseISO()`,
  иначе UTC сдвинет день.
- В `state` и localStorage — только plain-объекты: `Entity.create(...).toJSON()`.
  `store.commit()` клонирует через `structuredClone`, экземпляры классов туда
  класть нельзя.
- `js/reports/*` не импортируют DOM. «Остаток на конец» в ДДС и активы баланса
  считаются через `totalBalance()`/`accountBalance()` с одной датой и обязаны
  совпадать.
- Переводы не входят в P&L и итоги ДДС; показываются справочной строкой.
- Пользовательский текст — только `textContent` или `el(tag, { text })`,
  не `innerHTML`.
- CSS: примитивы `--gray-*`/`--brand-*` → семантика `--color-*`; тёмная тема
  переопределяет только семантику. Теней и градиентов нет: объём — слои
  `bg → surface → surface-muted` и 1 px граница. Для текста и иконок —
  `--color-accent-text`, для заливок — `--color-accent`. Один брейкпоинт `640px`,
  контент и таббар — `--container-max: 560px`.
- Навигация только через hash: History API на статическом хостинге даст 404.
- Скроллится только `#app`; сброс — `app.scrollTop`, не `window.scrollTo`.

## Поведение

- Обзор: «Всего на счетах» — все счета за всё время (`totalBalance()`); доходы,
  расходы и список — за выбранный месяц, список — 8 последних, «Все» открывает
  журнал на том же месяце.
- Журнал `#/transactions` — подэкран обзора, не вкладка: кнопка «Назад», активна
  «Обзор», все операции месяца без лимита. Фильтры и месяц — локальное состояние,
  в URL не пишутся.
- Месяц обзора, журнала и календаря — локальное состояние `YYYY-MM`; переключение
  не меняет hash и не сбрасывает скролл.
- Overlay (`#/add`, `#/edit/{id}`, `#/calendar/add`, `#/calendar/edit/{id}`)
  оставляет под собой текущий экран; при прямом входе — Dashboard или календарь.
  Закрытие — `router.back()`.
- Форма — `<dialog>` в top layer: `showModal()`, focus trap, возврат фокуса на `+`
  или строку; `#app` блокируется классом `is-sheet-open`.
- Дата по умолчанию — сегодня на текущем месяце, первое число на другом; после
  сохранения обзор и журнал переключаются на месяц операции. Правка сохраняет
  `createdAt` и обновляет `updatedAt`.
- Архивные счета входят в итоги; в форме добавления — только активные, в
  редактировании — ещё и архивные, на которые ссылается операция. Счёт: название
  1–40 символов, уникально без учёта регистра; остаток ≥ 0; `archived` — только
  отдельной кнопкой.
- `settings.currency` — только отображение; обязательства пустые (0), кредитную
  логику не добавлять без миграции схемы.
- Повторения: 31-е в коротком месяце → последний день; 29 февраля → 28 в
  невисокосный; `endDate` включительно; вхождения не раньше месяца создания серии.
  Месяц создания — локальный месяц `createdAt`, то есть тот, что видел пользователь;
  UTC сдвинул бы границу на стыке месяца.
- «Оплатить» создаёт операцию с сегодняшней датой, дата вхождения остаётся сроком;
  «Пропустить» и «Вернуть» операций не создают; правка серии не трогает оплаченные
  вхождения.
- Удаление оплаченной операции или смена `type`/`accountId`/`date` возвращает
  вхождение в «ожидает»; сумма, категория и заметка связь не рвут.
- Прогноз = текущий баланс + неоплаченные вхождения до конца месяца, включая
  просрочку; для прошедших месяцев блок скрыт. Ближайшие платежи: до трёх, сначала
  просрочка, затем 30 дней; клик открывает календарь на дате.
- Календарь — вкладка таббара: сетка месяца, список дня, «Требует внимания»,
  сводка и прогноз; месяц и день в URL не пишутся.
- Таббар: 4 колонки (Обзор, Календарь, Отчёты, `+`); настройки — шестерёнка в
  шапке, не вкладка; активное состояние — `aria-current="page"`.
- Тема: `settings.theme` = `light | dark | system`; JS ставит `data-theme` на
  `<html>` и обновляет `meta[name="theme-color"]` из `--color-bg`; `system`
  разрешается в JS.
- Safe mode: `readState()`/`loadState()` отдают статус `empty | ok | forward |
  corrupt | no-space`; `forward` определяется по `schemaVersion` до миграции, ошибка
  разбора или проверки — `corrupt`. На `forward`/`corrupt` store и роутер не
  создаются, шелл и таббар скрыты, тема системная; экран объясняет причину и
  предлагает экспорт сырых данных, импорт копии, восстановление `pre-v4` и сброс.
  Непустой ключ на старте не перезаписывается. Импорт и восстановление в статусе
  `forward` сначала подтверждаются (в предупреждении — имя файла и замена данных
  более новой версии); в `corrupt` — без confirm. Успех — `replace(persist)` и
  обычный режим на новом `rev` без перезагрузки. Событие хранилища в safe mode
  только показывает баннер. `no-space` — копия `pre-v4` не помещается: v4 не
  пишется, доступна только выгрузка исходных данных, без импорта и сброса.
- Схема v4 без потери полей: `migrate()` возвращает `{ state, warnings }`, сохраняет
  неизвестные поля сущностей и верхнеуровневые ключи, проставляет умолчания
  (`obligations`, `obligationAdjustments`, `account.savingsRateBp`,
  `category.system/mark`, поля разбивки платежа и нормы у операции,
  `plannedPayment.obligationId/archived/anchorDay`, `obligation.archived`). Если на
  месте поля v4 значение не той формы, подставляется умолчание, а путь и причина
  попадают в `warnings[]`; список показывается блоком «Данные обновлены» в настройках
  один раз (отметка — в `finance-tracker:meta`). Правка операции и плана сливает
  текущие поля с новыми, поэтому чужие ключи не теряются.
- Копия `pre-v4`: перед первой записью v4 сырой старый файл копируется в
  `finance-tracker:pre-v4`; копия не перезаписывается и сама не удаляется. В
  настройках её можно восстановить (confirm, `replace(persist)` на новом `rev`,
  копия остаётся) или удалить (confirm); отмена ничего не меняет.
- Фиксированный таббар перекрывает низ `#app`: при новом fixed-элементе снизу
  пересчитать `--scroll-clearance` и `--toast-bottom`.

## Известные грабли

- Палитра живёт в трёх местах: CSS-токены, `manifest.json`
  (`theme_color`/`background_color`) и PNG `icons/*`. Меняя акцент, обновляй все три.
- PWA и `navigator.storage.persist()` — только в secure context (`localhost`/HTTPS).
  На `http://192.168.x.x` service worker не регистрируется, это ожидаемо.
- `navigator.storage.persist()` — просьба: статус в настройках обязан различать
  «защищено» и «может быть очищено».
- `[hidden] { display: none !important }` обязателен, иначе `display` у `.screen`
  перебьёт атрибут.
- Поля — 16 px и `inputmode="decimal"`: иначе iOS зумит и ломает запятую.
  Тач-цели ≥ 44 px, `env(safe-area-inset-*)` в шапке и таббаре.
- `openingBalance` — остаток «до всей истории». Счёт с операциями или планами не
  удаляется, только архив; удаление счёта с остатком — только через
  `deleteAccount(id, { allowNonZero: true })` после confirm, иначе баланс не
  спишется.
- Удаление категории обнуляет `categoryId` у операций и планов и удаляет бюджеты;
  `type` операций не меняется.
- Импорт всегда подтверждается и заменяет состояние целиком. `AbortError` в
  `shareState()` — отмена: без тоста и без даты копии.
- `readState()` не глотает ошибку в `empty`: исключение чтения, битый JSON и
  провал `validateState` — это `corrupt`, иначе `loadState()` посеет seed поверх
  данных. `finance-tracker:corrupt` хранит первую копию и не перезаписывается;
  safe mode копии `:corrupt`/`:pre-v4` не удаляет. `PRE_V4_KEY` — общая константа:
  `loadState()` пишет её перед первой записью v4 и только если копии ещё нет; при
  нехватке места возвращает `no-space` и не трогает живой ключ; удаление — только
  `removePreV4Copy()` из настроек после confirm. `migrate()` не бросает на чужом
  значении поля v4: заменяет умолчанием и пишет `{ path, message }` в `warnings`.
- Новое поле модели легко потерять: `create()`/`toJSON()` собирают поля поимённо.
  Добавляя поле, обновите обе стороны и слияние в `updateTransaction`/
  `updatePlannedPayment`, иначе правка снова пересоберёт запись без него.
- `localStorage` привязан к origin, а не к пути: проекты на
  `prokiller882.github.io` делят хранилище, у приложения ключ `finance-tracker:v1`.
  Переезд на свой домен требует экспорта/импорта.
- Изменение `openingBalance` у счёта с операциями — только после confirm:
  пересчитываются баланс и отчёты за всю историю.

## Git-доступ (вне bmad)

- `git push` работает из WSL без токена в чате: `~/.gitconfig` → helper
  `~/.local/bin/git-credential-manager-wsl` → Windows Credential Manager
  (запись `git:https://github.com`). Токенов в репозитории и в WSL нет.
- Токен не запрашивать у пользователя. Если пуш просит логин — токен истёк,
  авторизуйтесь в окне GCM один раз; чинить надо helper, а не вставлять PAT.
- MCP не заменяет пуш: GitHub MCP — только API (issues/PR), не `git push`.
