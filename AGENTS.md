# AGENTS.md

Ванильный HTML/CSS/JS SPA для личных финансов: без сборки, npm и фреймворков. Данные — в localStorage.

Документ поддерживается вместе с кодом: изменение маршрутов, разметки, инвариантов или чек-листа фиксируется здесь в той же правке.

## План развития

- [ROADMAP.md](./ROADMAP.md) — текущий статус, ближайшая задача перед релизом и функциональный бэклог.

## Запуск

- ES-модули не работают по `file://`. Только локальный сервер:
  `python3 -m http.server 8080` → http://localhost:8080
- PWA и service worker работают только в secure context: на `localhost` или по HTTPS. На `http://192.168.x.x` они недоступны, приложение откроется как обычная страница.
- Продакшен — GitHub Pages, проект `finance`:
  https://prokiller882.github.io/finance/
  Репозиторий публичный, сборки нет; `.nojekyll` отключает Jekyll. Service worker ограничен путём `/finance/` и не трогает другие проекты на `prokiller882.github.io`.
- Node/npm в окружении не установлены: `npm test` не существует. Проверка — ручная (чек-лист ниже).

## Карта

- `index.html` — статический каркас экранов внутри `.app-shell` (шапка + скроллящийся `#app`), нижний таббар с кнопкой добавления, переключатели месяца на обзоре и в журнале; таббар, тост и модальная форма `#tx-sheet` — вне шелла. Разметка живёт здесь, JS только наполняет контейнеры.
- `js/app.js` — bootstrap, глобальные `actions`, тема (`data-theme`), тосты, синхронизация вкладок; создаёт экраны и overlay формы операции, связывает Dashboard и журнал.
- `js/router.js` — hash-роутер: `#/dashboard`, `#/transactions`, `#/reports/{balance|income|cashflow}`, `#/settings`; `#/add` — overlay создания, `#/edit/{id}` — overlay редактирования поверх текущего экрана. `#/reports` и неизвестные пути заменяются через `replaceState`.
- `js/store.js` — единственный источник истины: `commit()` клонирует состояние, сохраняет и только потом публикует.
- `js/schema.js` — `SCHEMA_VERSION` (сейчас `2`), общий для seed и storage; storage реэкспортирует его.
- `js/storage.js` — localStorage, ключ `finance-tracker:v1`, `SCHEMA_VERSION`, `migrate()`, `validateState()`, `StorageError`; повреждённые данные уходят в `finance-tracker:corrupt`; импорт/экспорт JSON — `parseImportFile()`/`downloadState()`/`shareState()`; метаданные копий — `readMeta()`/`markExported()` в отдельном ключе `finance-tracker:meta`.
- `js/pwa.js` — регистрация service worker, запрос постоянного хранилища (`persist()`/`persisted()`) и возраст последней копии; не трогает состояние финансов.
- `manifest.json`, `sw.js`, `icons/*` — PWA: установка на Android, офлайн-кэш оболочки, иконки 192/512/maskable. `.nojekyll` нужен для GitHub Pages.
- `js/models/*` — классы `Transaction`, `Category`, `Budget`: `create()`, `fromJSON()`, `validate()`, `toJSON()`. В `state` и localStorage остаются plain-объекты, потому что `store.commit()` использует `structuredClone`.
- `js/screens/*` — фабрики экранов, контракт `{ id, title, titleFor?(path), init(root), show?(path), render() }`. `init` вызывается один раз, `show` — при входе на экран, `render` — при входе и на каждое изменение store. `titleFor` нужен отчётам для заголовка по маршруту. Dashboard и журнал дополнительно отдают `getMonth()`/`setMonth()`.
- `js/screens/settings.js` — настройки: счета (добавление, редактирование, архив, удаление), категории, валюта/тема, резервные копии и статус хранилища, импорт/экспорт/сброс.
- `js/components/transactionSheet.js` — компонент модальной формы операции: `open({ basePath, mode, transactionId })`, `close()`, `render()`, `isOpen()`. Не является экраном и живёт в `<dialog>`.
- `js/components/transactionRow.js` — общая строка операции для обзора и журнала: сумма, подпись, ссылка `#/edit/{id}` и удаление через `data-action="delete-tx"`.
- `js/journal.js` — чистая выборка журнала по месяцу, типу, счёту, категории и поисковой строке; DOM и localStorage не трогает.
- `js/accounts.js` — чистая валидация счёта (`normalizeAccountInput()`) и проверка ссылок операций (`accountHasOperations()`); DOM и localStorage не трогает.
- `js/reports/*` — чистые функции отчётов, DOM и localStorage не трогают; `overview.js` собирает сводку обзора.
- `js/format.js`, `js/dom.js`, `js/labels.js`, `js/seed.js`, `js/util.js` — деньги/даты/периоды и ключи месяцев (`monthKey`, `monthRange`, `shiftMonthKey`), форматирование суммы для input (`formatAmountInput`), DOM-хелперы и SVG-иконки (`el`, `icon`), подписи и склонения, стартовые данные, `newId()`.

## Инварианты

- Деньги — целые копейки (`125050` = 1250,50 ₽). Никаких float; парсинг только через `parseAmount()`.
- Даты — строки `YYYY-MM-DD`, фильтрация сравнением строк. Для арифметики — `parseISO()`, иначе UTC-сдвиг.
- `Transaction`: `type` = `expense | income | transfer`, `amount` — целые копейки, `accountId`/`toAccountId`, `categoryId` (может быть `null` после удаления категории), `note`, `date`, `createdAt`, `updatedAt`. Для перевода `categoryId` всегда `null`, счета различаются.
- `Category`: обязательные `kind` (`expense | income`), `color` (`#RRGGBB`) и `icon`; цвет/иконка имеют дефолты и нужны для будущего UI. Название уникально в рамках `kind` без учёта регистра.
- `Budget`: месячный бюджет на расходную категорию; `period` — `YYYY-MM`, `amount` — целые копейки, пара `categoryId + period` уникальна. UI бюджетов пока нет.
- `js/models/*` не хранят экземпляры в `state`: действия вызывают `Entity.create(...).toJSON()`, storage валидирует и сохраняет plain-объекты. Нельзя класть экземпляры классов в `app.state` без гидрирования после `structuredClone`.
- `reports/*` не импортируют DOM. Баланс и ДДС считают остатки через `accountBalance()`/`totalBalance()`, поэтому «остаток на конец» в ДДС обязан совпадать с активами в балансе на ту же дату. Это главная проверка при правках отчётов.
- Dashboard: «Всего на счетах» — все счета за всё время (`totalBalance()`); доходы, расходы и список операций — только за выбранный месяц. Переводы показываются в списке, но не входят в доходы/расходы; список ограничен 8 последними операциями, ссылка «Все» открывает журнал на том же месяце.
- Журнал `#/transactions` — не вкладка таббара, а подэкран обзора: в шапке видна кнопка «Назад», активна вкладка «Обзор». Показывает все операции выбранного месяца без лимита 8; фильтры (тип, счёт, категория, поиск) и месяц — локальное состояние экрана, в URL не пишутся.
- Выбранный месяц обзора и журнала — локальное состояние `YYYY-MM` в экземплярах экранов, по умолчанию текущий. Оно не пишется в URL и не сохраняется после reload; переключение месяцев не сбрасывает скролл и не меняет hash.
- `#/add` и `#/edit/{id}` — overlay, а не отдельные экраны: под ними остаётся текущий экран (Dashboard/журнал/отчёты/настройки), при прямом открытии/перезагрузке — Dashboard. Закрытие идёт через `router.back()`, поэтому работают крестик, Esc, backdrop, сохранение и кнопка «Назад» браузера.
- Форма операции — нативный `<dialog>` в top layer: `showModal()`, `::backdrop`, focus trap, возврат фокуса на `+` для создания и на строку/заголовок для редактирования, блокировка `#app` классом `is-sheet-open`. На мобильном это bottom sheet с внутренним скроллом и safe-area в футере, на `>=640px` — центрированное модальное окно.
- Дата по умолчанию в форме: сегодня на текущем месяце, первое число выбранного месяца на другом. После сохранения Dashboard и журнал переключаются на месяц операции, даже если операция добавлена с другого экрана.
- Редактирование сохраняет `createdAt` операции и обновляет `updatedAt`; `Transaction.create()` остаётся единственной точкой валидации. Операцию без категории можно сохранить как «Без категории».
- Архивные счета входят в итоги и отчёты; в форме добавления — только активные, в форме редактирования — ещё и архивные, на которые уже ссылается операция.
- Удаление счёта с операциями (`accountId`/`toAccountId`) запрещено — только архив. Счёт без операций удаляется: при нулевом балансе обычным подтверждением, при ненулевом — только через `deleteAccount(id, { allowNonZero: true })` после confirm со списанием остатка. `openingBalance` входит в баланс, поэтому удаление с остатком уменьшает итоговый баланс.
- Редактирование счёта идёт в существующей форме добавления: название, тип и `openingBalance`; `archived` меняется только отдельной кнопкой. Название — 1–40 символов, уникально без учёта регистра; остаток — целые копейки `>= 0`, для явного нуля нужен `parseAmount(raw, { allowZero: true })`.
- Изменение `openingBalance` у счёта с операциями разрешено, но только после confirm: баланс и отчёты пересчитываются за всю историю. Смена только названия или типа — без предупреждения.
- В строке счёта основная часть — кнопка `data-action="edit-account"`, архив и удаление остаются отдельными кнопками, чтобы на 360 px не появлялась третья.
- `openingBalance` — остаток «до всей истории», без привязки к дате.
- `settings.currency` — только отображение; конвертации между валютами нет.
- Обязательства в балансе намеренно пустые (0). Не добавлять кредитную логику без миграции схемы.
- Удаление категории обнуляет `categoryId` у операций и удаляет связанные бюджеты; сами операции не удаляются.
- Удаление категории не меняет `type` операций: после обнуления `categoryId` они остаются в P&L/ДДС как «Без категории».
- PWA: `manifest.json` и `sw.js` лежат в корне проекта, `start_url`/`scope` — `./`, поэтому приложение работает и в подпапке `/finance/`. Регистрация service worker — только при `window.isSecureContext`; на LAN по HTTP PWA и `storage.persist()` недоступны.
- `sw.js` кэширует оболочку по списку `PRECACHE`: при добавлении нового JS-модуля его нужно внести туда и поднять версию `CACHE`, иначе офлайн-загрузка упадёт. Стратегия — network-first с fallback на кэш; навигация офлайн отдаёт `index.html`.
- Service worker ограничен scope `/finance/`. Нельзя выкладывать приложение в корень `prokiller882.github.io`: тогда SW с scope `/` начнёт перехватывать `/portfolio/` и `/sleep_tracker_rr_2027/`.
- `navigator.storage.persist()` — просьба, а не гарантия: браузер может отказать. Статус в настройках должен честно различать «защищено» и «может быть очищено»; ручная очистка данных Chrome удаляет localStorage в любом случае.
- `finance-tracker:meta` — отдельный ключ для `lastExportAt`; в экспорт не входит, при «Сбросить всё» очищается. Дата последней копии старше 30 дней подсвечивается предупреждением.
- Экспорт идёт через `shareState()`: на Android — системное меню «Поделиться», иначе скачивание. `AbortError` означает отмену — тост не показывать и дату копии не обновлять. Импорт всегда подтверждается, потому что заменяет состояние целиком.
- `localStorage` привязан к origin (схема + хост + порт), а не к пути. Все проекты GitHub Pages на `prokiller882.github.io` делят хранилище, но ключ `finance-tracker:v1` у приложения свой. Переход на свой домен меняет origin — перед этим нужен экспорт/импорт.
- Навигация только через hash: History API на статическом хостинге даст 404 при обновлении.
- Пользовательский текст — только `textContent` или `el(tag, { text })`, не `innerHTML`.
- CSS-токены: примитивы (`--gray-*`, `--brand-*`) → семантика (`--color-*`); тёмная тема переопределяет только семантику. Для текста и иконок — `--color-accent-text`, для заливок — `--color-accent`. Старых `--accent`/`--muted`/`--surface-2` нет. Один брейкпоинт `640px`; контент и таббар ограничены `--container-max: 560px`.
- Каркас: `.app-shell` — grid `auto minmax(0,1fr)`, `100dvh`, `overflow: hidden`; шапка — верхний ряд, скроллится только `#app`. Таббар `position: fixed` вне grid и перекрывает низ `#app`, поэтому у `#app` есть `padding-bottom: var(--scroll-clearance)`; тост — `var(--toast-bottom)`. Новый fixed-элемент снизу требует пересчёта этих токенов.
- Шапка: колонки `var(--size-touch) 1fr var(--size-touch)`; у заголовка и спейсера явные `grid-column`, иначе скрытый `#back-btn` сдвинет заголовок.
- Таббар: 4 колонки — Обзор, Отчёты, `.tabbar__action` (+), Настройки; плавающего FAB нет — он перекрывал контент. Журнал не добавляет пятую вкладку, а открывается ссылкой с обзора. Активное состояние — `aria-current="page"`; `+` активно на `#/add`, на `#/transactions` активна «Обзор».
- Тема: `settings.theme` = `light | dark | system`; JS ставит `data-theme` на `<html>` и обновляет `meta[name="theme-color"]`. `system` разрешается в `app.js`; `prefers-color-scheme` в CSS не использовать.
- `[hidden] { display: none !important }` обязателен (иначе `display` у `.screen` перебьёт атрибут), `env(safe-area-inset-*)` учтён в шапке и таббаре, тач-цели ≥ 44 px, поля 16 px (`max(16px, 1rem)`) и `inputmode="decimal"` (иначе iOS зумит и ломает запятую). Фокус — через `:focus-visible` и `--color-focus-ring`.
- Скроллится только `#app` (`body { overflow: hidden }`). Для сброса скролла — `#app.scrollTop`, не `window.scrollTo`.
- Переводы: не входят в P&L и в итоговые поступления/списания ДДС, но показываются справочной строкой.

## Как расширять

- Новый экран: `section` внутри `<main id="app">` (`id="screen-<id>"`, `class="screen"`, `data-screen="<id>"`) → фабрика в `js/screens/` → регистрация в `screens` в `js/app.js` → маршрут и `tabFor()` в `js/router.js`. Если экран должен быть в таббаре — ссылка с `data-route` и ветка в `tabFor()`; если это подэкран, как журнал, — ссылка с другого экрана, `back: true` в маршруте и активная родительская вкладка. При изменении числа вкладок обновить `grid-template-columns` таббара (сейчас 4: три вкладки и `+`).
- Новый overlay: компонент в `js/components/` с `open(context)`/`close()`/`render()` → `overlays` в `js/app.js` → ветка `parseOverlay()`/`handleOverlay()` в `router.js` с базовым экраном и `router.back()` для закрытия. `open()` возвращает `false`, если контекст невалиден; роутер откатывается на базовый экран. Не добавлять overlay в `screens`.
- Новый отчёт: чистая функция в `js/reports/` → рендер в `js/screens/reports.js` → ключ в `REPORT_KEYS`/`REPORT_TITLES` и ссылка в `#report-tabs` → заголовок в `titleFor()`.
- Новая выборка/фильтр: чистая функция рядом с доменом (как `js/journal.js`) → экран только наполняет DOM; не смешивать фильтрацию с localStorage.
- Любая правка карты, инвариантов, маршрутов или способа запуска сопровождается обновлением этого файла и чек-листа ниже.
- Новое поле схемы: обновить `SCHEMA_VERSION` в `js/schema.js` и `migrate()`, не полагаться на то, что старые данные его содержат.
- Новая сущность: класс в `js/models/` с `create/fromJSON/validate/toJSON` → экспорт в `js/models/index.js` → проверка ссылок и уникальности в `validateState()` → миграция старого состояния и seed.
- Подписи счетов и количество операций — через `accountSubtitle()`/`operationsCount()` из `labels.js`, чтобы не дублировать тип счёта и не ломать склонение.
- Новый JS-модуль: добавить путь в `PRECACHE` в `sw.js` и поднять версию `CACHE`, иначе офлайн-режим сломается. После `git push` в `main` GitHub Pages пересобирает сайт; обновление service worker может занять несколько минут из-за кэша.

## Проверка после изменений

- Ширина 360 px: нет горизонтального скролла; последняя строка списка после прокрутки до конца выше таббара; safe-area учтена.
- Ширина 1024 px: контент и таббар выровнены по 560 px.
- Темы `light` / `dark` / `system`: `data-theme` и `meta theme-color` корректны, после reload выбор сохраняется.
- Переход по hash: `#app.scrollTop = 0`, активный пункт и `aria-current` корректны, фокус на заголовке; при возврате из `#/add`/`#/edit` скролл и фокус не сбрасываются.
- Добавить расход, доход и перевод → сверить суммы на обзоре, в журнале, в балансе, P&L и ДДС.
- Обзор: переключить месяц назад/вперёд и «Текущий» → меняются только доходы/расходы и список операций, «Всего на счетах» не меняется; переводы в списке есть, в суммах нет; пустой месяц показывает корректный текст.
- Обзор: ссылка «Все» открывает журнал на том же месяце; при 10 операциях в месяце на обзоре видно 8, в журнале — все 10.
- Журнал: переключить месяц, тип, счёт, категорию, ввести поиск и сбросить фильтры → список и счётчик совпадают; пустые состояния различаются.
- Журнал: удалить операцию → она исчезает из списка и отчётов; при ошибке сохранения успешный тост не показывается.
- Настройки: изменить название, тип и начальный остаток → строка, Dashboard, отчёты и форма операции показывают новые данные; `createdAt` существующих операций не меняется.
- Настройки: дубль названия (в другом регистре), пустое имя и отрицательный остаток отклоняются; остаток `0` принимается.
- Настройки: изменить начальный остаток счёта с операциями → отмена confirm оставляет данные, подтверждение пересчитывает баланс и отчёты; смена только имени или типа идёт без confirm.
- Настройки: удалить счёт без операций и с нулевым балансом → счёт исчезает из списка, отчётов и формы операции.
- Настройки: удалить счёт без операций с ненулевым остатком → confirm показывает сумму; отмена сохраняет счёт, подтверждение списывает остаток и уменьшает итоговый баланс.
- Настройки: попытка удалить счёт с операциями → отказ с тостом «отправьте его в архив», данные не меняются; архивный пустой счёт удаляется.

- PWA: на `localhost` или HTTPS манифест читается без ошибок, service worker активируется, приложение предлагает установку; на `http://192.168.x.x` SW не регистрируется и это ожидаемо.

- Android: установить приложение на главный экран, открыть в standalone-режиме, проверить, что данные те же, что во вкладке Chrome.
- Настройки: статус постоянного хранилища отображается честно; при отказе браузера есть предупреждение, а не ложное «защищено».

- Настройки: после копии появляется дата; старше 30 дней — предупреждение; «Сбросить всё» очищает дату копии.
